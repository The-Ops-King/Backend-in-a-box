# Fathom — verified facts (2026-10-07, from developers.fathom.ai)

| Fact | Detail |
|---|---|
| Base URL | `https://api.fathom.ai/external/v1` |
| Auth | header `X-Api-Key: <key>` (or `Authorization: Bearer`). Keys are made in Fathom → Settings → API Access, per user; a key sees that user's recordings plus what is shared with them / their team. For a team's calls, make the key on the team (owner) account. |
| Rate limits | 60 requests / 60 s overall; 30 / 60 s for "heavy" calls (transcript, summary, meetings with transcript included), can drop to 5 / 60 s at peak. Headers `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset`, `Retry-After`. |
| Create webhook | `POST /webhooks` `{ destination_url, triggered_for: ["my_recordings","my_shared_with_team_recordings","shared_team_recordings","shared_external_recordings"], include_transcript, include_summary, include_action_items, include_crm_matches }` (at least one include true). Returns `{ id, url, secret: "whsec_…", created_at, triggered_for, include_* }`. The secret is shown once. `DELETE /webhooks/{id}` → 204. Webhooks can also be made in Settings → API Access → Add Webhook. |
| Delivery headers | Standard Webhooks: `webhook-id`, `webhook-timestamp` (unix seconds), `webhook-signature` (`v1,<base64>`, space-separated during rotation). HMAC-SHA256 over `{id}.{timestamp}.{raw body}`, key = the `whsec_` secret base64-decoded. Five-minute timestamp tolerance. Verified by `platform/src/engine/webhooks/standard.ts` (shared with Whop). |
| Payload | One event, "new meeting content ready": the Meeting object. `recording_id`, `title`, `meeting_title`, `meeting_type`, `url` (login), `share_url` (public link), `created_at`, `scheduled_start_time`, `scheduled_end_time`, `recording_start_time`, `recording_end_time`, `calendar_invitees_domains_type` (all / only_internal / one_or_more_external), `calendar_invitees[{ name, email, email_domain, is_external, matched_speaker_display_name }]`, `recorded_by { name, email, email_domain, team }`, `transcript[{ speaker { display_name, matched_calendar_invitee_email }, text, timestamp "HH:MM:SS" }]` (when included), `default_summary { template_name, markdown_formatted }`, `action_items[{ description, user_generated, completed, recording_timestamp, recording_playback_url, assignee }]`, `crm_matches`. |
| List meetings | `GET /meetings?include_transcript=&include_summary=&created_after=&recorded_by[]=&cursor=` — same Meeting object; useful for a backfill. |
| Our endpoints | `POST /api/webhooks/fathom/<companyId>` (secret bound as `secret.fathom_webhook`; install registers the webhook when given `recording: { source: "fathom", apiKey }` and `PUBLIC_URL` is set, and remembers its id as `fathom.webhook_id`). `POST /api/webhooks/zapier/<companyId>/recording` for a Zap (Fathom "New Transcript/Recording" trigger → Webhooks by Zapier), authenticated with the company's inbound secret. |
| Matching | No CRM id anywhere in the payload. The engine matches by invitee email → invitee name → the recorder's own calendar (D22). `is_external: false` and roster emails are treated as staff. |
